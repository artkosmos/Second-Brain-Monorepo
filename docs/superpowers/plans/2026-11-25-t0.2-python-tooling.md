# T0.2 Python tooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Собрать окружение бэкенда одной командой `uv sync` внутри репозитория и проверять код ruff, mypy strict и pre-commit.

**Architecture:** Единственный манифест зависимостей — `backend/pyproject.toml`. Зафиксированные версии — `backend/uv.lock`. Виртуальное окружение — только `backend/.venv`, его создаёт `uv sync`. Старый общий venv `~/Work/Python/Backend/.venv` и `backend/package.json` больше не используются. Раскладку каталогов не менять: `src/` появится в T0.3.

**Tech Stack:** uv, Python 3.14, ruff, mypy (плагин `pydantic.mypy`), pre-commit, pytest, pytest-postgresql.

## Global Constraints

- Спека: `docs/tasks/P0/T0.2-python-tooling.md`. Роадмап: Python 3.14, пока у зависимостей нет колёс 3.15 (`docs/ROADMAP.md`, §6).
- Все Python-пакеты ставить только в `backend/.venv` через `uv sync` / `uv add`. Запрещены `pip install`, `uv pip install --system`, `uv tool install`, `pipx`, установка в `~/Work/Python/Backend/.venv` и любые глобальные копии ruff, mypy, pre-commit, pytest.
- Бинарь `uv` — установщик, не зависимость проекта. Если его нет в `PATH`, поставить официальный бинарь uv. Сам uv в `.venv` не класть.
- `uv sync` скачивает интерпретатор 3.14 в кэш uv и создаёт `backend/.venv` на нём. Это не системный site-packages.
- Не переносить код в `src/`. Не делать feature-модули. Не трогать фронт, compose и миграции, кроме правок, без которых ruff или mypy не проходят.
- Не копировать `~/Work/Python/Backend/requirements.txt` в репозиторий. Там заморожены и прямые, и транзитивные пакеты. В `pyproject.toml` только прямые зависимости с нижней границей. Точные версии пишет `uv.lock`.
- Не добавлять пакеты, которые код не импортирует: `sentry-sdk`, `fastapi-cli`, `pytest-asyncio`, `python-multipart`.
- `# type: ignore` только с кодом ошибки и строкой в `docs/tech-debt.md`. Глобальный `ignore_missing_imports = true` запрещён.
- Коммит делать только если пользователь в той сессии явно попросил. Не ставить `✅` в `docs/ROADMAP.md`.
- Секреты не коммитить. `.venv/` уже в корневом `.gitignore`. `uv.lock` коммитить.

## Task 5: pre-commit

**Files:**
- Create: `.pre-commit-config.yaml` в корне репозитория

**Interfaces:**
- Consumes: `ruff` и `pre-commit` из `backend/.venv`
- Produces: `uv run --project backend pre-commit run --all-files` с кодом 0

Хук не скачивает свой ruff. Он вызывает `uv run --project backend`, то есть бинарь из `backend/.venv`. Проверки больших файлов и приватных ключей идут из репозитория `pre-commit-hooks`: это маленькие хуки в кэше pre-commit (`~/.cache/pre-commit`), не установка в системный Python. mypy в хук не добавлять: карточка оставляет его на ручной запуск и будущий CI (T0.4).

- [ ] **Step 1: Конфиг в корне репозитория**

`.pre-commit-config.yaml`:

```yaml
repos:
  - repo: local
    hooks:
      - id: ruff
        name: ruff
        entry: uv run --project backend ruff check --fix
        language: system
        types_or: [python, pyi]
        files: ^backend/
      - id: ruff-format
        name: ruff-format
        entry: uv run --project backend ruff format
        language: system
        types_or: [python, pyi]
        files: ^backend/

  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v6.0.0
    hooks:
      - id: check-added-large-files
      - id: detect-private-key
```

Если тег `v6.0.0` не существует, взять последний стабильный тег этого репозитория и записать его в `rev`. Не ставить `repo: local` на эти два хука и не копировать их код в репозиторий.

- [ ] **Step 2: Поставить git-хук из venv**

Из корня репозитория:

```bash
uv run --project backend pre-commit install
uv run --project backend pre-commit run --all-files
```

Ожидание: код 0. `pre-commit install` пишет хук в `.git/hooks/` этого клона и должен вызывать pre-commit из `backend/.venv`. Проверка: `head -n 20 .git/hooks/pre-commit` содержит путь к `backend/.venv` или вызов `uv`. Если хук зовёт системный `pre-commit`, удалить хук и повторить команду через `uv run`.
