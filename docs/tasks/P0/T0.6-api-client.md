# T0.6 Контракт OpenAPI → TypeScript + TanStack Query

**Фаза:** P0 · **Слой:** frontend, backend · **Зависит от:** T0.3 · **Размер:** L

## Контекст
Типы `shared/types/notes.ts` написаны руками и разъедутся с бэкендом при первом изменении схемы.

## Цель
Фронт получает типы и клиент API из OpenAPI-схемы бэкенда; рассинхрон ловится компилятором и CI.

## Что сделать
1. Бэкенд: у всех эндпоинтов явные `response_model`, `operation_id` (через `generate_unique_id_function`), теги. Схема должна быть «чистой» для генератора.
2. Скрипт выгрузки схемы без запуска сервера: `uv run python -m app.scripts.export_openapi > frontend/openapi.json`.
3. Генератор на выбор (обоснуй в ADR `0001-api-client-codegen.md`): [orval](https://orval.dev/) (генерирует хуки TanStack Query) или [openapi-typescript](https://openapi-ts.dev/) + `openapi-fetch`.
4. TanStack Query: `QueryClientProvider`, ключи запросов, инвалидация после мутаций, `credentials: 'include'` в общем fetcher, обработка 401 → logout.
5. Удалить ручные типы и `services/notes.ts`, где их заменил клиент.
6. CI: job проверяет, что `openapi.json` в репо совпадает со свежей выгрузкой.

## Критерии приёмки
- [ ] Поменял поле в Pydantic-схеме → фронт не компилируется, пока не перегенерируешь клиент
- [ ] Список заметок и CRUD работают через TanStack Query, без ручного `useEffect` + `fetch`
- [ ] CI ловит рассинхрон схемы
- [ ] ADR 0001 написан
