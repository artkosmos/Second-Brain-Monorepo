**Фаза:** P0 · **Слой:** infra · **Зависит от:** — · **Размер:** S

## Контекст
Код живёт в `Backend/lessons/lesson_19_auth_frontend/`, git нет, зависимости ставятся в общий `.venv` уровня `Backend/`.

## Цель
Один git-репозиторий `second-brain` на GitHub со всем кодом приложения, без секретов в истории.

## Что сделать
1. В `~/Work/Python/second-brain/` (папка `docs/` уже есть) выполнить `git init`.
2. Перенести код урока 19:
   - бэкенд → `backend/` (пока плоско, как есть; раскладка по модулям — T0.3);
   - фронт → `frontend/`;
   - `compose.yaml` (Postgres + pgAdmin) → `infra/compose.yaml`.
3. Корневой `.gitignore`: `.env*` (кроме `*.example`), `.venv/`, `__pycache__/`, `node_modules/`, `.next/`, `*.tsbuildinfo`, `.pytest_cache/`.
4. Проверить, что секреты (`.env`, `.env.supabase`) не попадут в первый коммит: `git status` перед `git add`.
5. Корневой `README.md`: что за проект, как поднять локально (БД, API, фронт), ссылка на `docs/ROADMAP.md`.
6. Создать репозиторий на GitHub (приватный или публичный — твой выбор), `git push`.
7. Защита ветки `main`: только через PR, обязательный зелёный CI (включить после T0.4).

## Критерии приёмки
- [ ] Репозиторий на GitHub, история начинается с чистого коммита без секретов
- [ ] `infra/compose.yaml` поднимает Postgres; API и фронт стартуют по README
- [ ] Старые тесты урока 19 проходят из `backend/`

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| `git add .` до `.gitignore` | `.env` с паролем Supabase уйдёт в историю навсегда |
| Копировать `node_modules` / `.venv` | мусор в репо, ломается на другой машине |

Если секрет всё-таки попал в коммит — не «удалять следующим коммитом», а сменить пароль/ключ и переписать историю до первого push.
