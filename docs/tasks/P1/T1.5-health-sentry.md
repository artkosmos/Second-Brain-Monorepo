# T1.5 Healthchecks, graceful shutdown, Sentry

**Фаза:** P1 · **Слой:** backend, system-design · **Зависит от:** T1.2 · **Размер:** M

## Цель
Платформа знает, когда инстанс готов принимать трафик; деплой не обрывает запросы; ошибки фронта и бэка видны в одном месте.

## Что сделать
1. `GET /health/live` — процесс жив (без зависимостей). `GET /health/ready` — БД отвечает на `SELECT 1` с таймаутом; 503, если нет.
2. Платформа использует `ready` для проверки перед переключением трафика.
3. Graceful shutdown: при SIGTERM перестать принимать запросы, дождаться текущих, закрыть пул БД (lifespan). Проверить: долгий запрос во время деплоя не обрывается.
4. Sentry: бэкенд (`sentry-sdk[fastapi]`) и фронт (`@sentry/nextjs`), `environment` и `release` = SHA, `request_id` как tag, PII выключено.
5. Source maps фронта загружаются в Sentry при сборке.

## Критерии приёмки
- [ ] Остановил БД → `ready` 503, `live` 200
- [ ] Искусственная ошибка (`/debug/boom`, не в prod) видна в Sentry с `request_id` и release
- [ ] Ошибка фронта в Sentry показывает исходный TS, а не минифицированный код

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| `live` проверяет БД | упала БД → платформа перезапускает все инстансы по кругу |
| `ready` без таймаута | зависшая БД вешает и healthcheck |
