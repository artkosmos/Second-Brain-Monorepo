# T1.2 API на PaaS, БД на Supabase

**Фаза:** P1 · **Слой:** infra, backend · **Зависит от:** T1.1 · **Размер:** M

## Цель
API доступен по HTTPS в двух окружениях, миграции применяются автоматически и блокируют деплой при ошибке.

## Что сделать
1. Выбрать Fly.io или Render — ADR `0002-api-hosting.md` (цена, регион рядом с Supabase, холодный старт, release-команды).
2. Два приложения: `second-brain-api-staging`, `second-brain-api-prod`.
3. Миграции как release-шаг (`release_command` во Fly / pre-deploy в Render). Если миграция упала — деплой не продолжается.
4. Секреты только через секреты платформы. `APP_ENV=staging|prod`.
5. Подключение к Supabase: пулер (Supavisor) в transaction mode для приложения, прямое подключение для миграций. Разобраться, почему с transaction pooler нельзя prepared statements, и настроить драйвер.
6. Ограничить размер пула соединений под лимиты Supabase.

## Критерии приёмки
- [ ] `https://<api-staging>/health` отвечает 200
- [ ] Сломанная миграция не выкатывает новую версию кода
- [ ] В README: как задеплоить руками и где лежат секреты (без значений)
