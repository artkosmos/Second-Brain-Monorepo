# T1.3 Фронт на Vercel, cookie на проде

**Фаза:** P1 · **Слой:** frontend, infra · **Зависит от:** T1.2 · **Размер:** M

## Контекст
Фронт на `*.vercel.app`, API на `*.fly.dev` — это разные сайты. HttpOnly cookie с `SameSite=Lax` браузер на cross-site fetch не отправит, а `SameSite=None` блокируют браузеры с защитой от third-party cookies.

## Цель
Браузер ходит только на домен фронта; cookie авторизации first-party и работают на проде.

## Что сделать
1. В `next.config.ts` — `rewrites`: `/api/:path*` → `${API_ORIGIN}/:path*`.
2. Сгенерированный клиент (T0.6) использует относительный `/api`. В local — тот же rewrite на `localhost:8000`; CORS для браузера больше не нужен (оставить только для `/docs` при необходимости).
3. Cookie: `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`; без `Domain` (host-only).
4. Бэкенд за прокси: доверять `X-Forwarded-*` только от прокси (`--forwarded-allow-ips`); проверить, что `request.url.scheme == "https"`.
5. Два окружения Vercel: production (prod API) и preview (staging API).
6. Security headers на фронте: CSP (хотя бы report-only), `X-Content-Type-Options`, `Referrer-Policy`.

## Критерии приёмки
- [ ] Register → login → CRUD заметок работают на staging-домене по HTTPS
- [ ] В DevTools cookie помечена `Secure; HttpOnly; SameSite=Lax`
- [ ] Ни один запрос из браузера не идёт напрямую на домен API
