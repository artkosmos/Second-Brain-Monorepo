# T1.4 CD: preview, staging, prod

**Фаза:** P1 · **Слой:** infra · **Зависит от:** T0.4, T1.3 · **Размер:** M

## Цель
Merge в `main` автоматически уезжает на staging, git tag — на prod после ручного подтверждения; после каждого деплоя прогоняется smoke-тест.

## Что сделать
1. `.github/workflows/deploy.yml`:
   - `push` в `main` после зелёного CI → деплой API на staging (фронт staging деплоит Vercel);
   - tag `v*.*.*` → деплой API на prod + production-деплой Vercel;
   - GitHub Environments `staging` / `prod`; для `prod` — required reviewer (ты сам) как ручной gate.
2. Smoke-тест после деплоя: `scripts/smoke.py` (httpx) — `/health`, register временного пользователя, создать / прочитать / удалить заметку. Упал → job красный.
3. Образ тегируется SHA коммита; версия (`git describe`) видна в `GET /health`.
4. Preview фронта на каждый PR (Vercel), работает против staging API.
5. Changelog: GitHub Release с автогенерацией заметок из PR.

## Критерии приёмки
- [ ] Merge в `main` → через несколько минут изменения на staging без ручных действий
- [ ] `git tag v0.1.0 && git push --tags` → prod после ручного approve
- [ ] `GET /health` показывает версию и SHA
- [ ] Красный smoke-тест виден в Actions
