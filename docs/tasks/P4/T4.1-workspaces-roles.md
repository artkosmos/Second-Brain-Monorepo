# T4.1 Workspaces и роли

**Фаза:** P4 · **Слой:** backend, frontend · **Зависит от:** P2 · **Размер:** L

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы.

## Backend
- `workspaces`, `workspace_members` (role: owner / editor / viewer).
- Страницы принадлежат workspace, а не пользователю; при регистрации создаётся личный workspace; миграция существующих данных.
- Зависимость `require_role(Role.EDITOR)`.
- Во всех запросах фильтр по `workspace_id`; тест на IDOR для каждого эндпоинта.

## Frontend
- Переключатель workspace, настройки участников.
- UI скрывает действия, недоступные роли (но защита — на бэке).

## Критерии приёмки
- [ ] Viewer получает 403 на запись
- [ ] Чужой workspace → 404 (не раскрываем существование)
- [ ] У workspace всегда есть хотя бы один owner (нельзя удалить последнего)
