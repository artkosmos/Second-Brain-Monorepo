# T4.C2 Challenge: Passkeys (WebAuthn)

**Фаза:** P4 · **Слой:** challenge · **Зависит от:** T4.6 · **Размер:** M

## Что сделать
- Регистрация и вход по passkey через [`py_webauthn`](https://github.com/duo-labs/py_webauthn): `POST /auth/passkeys/register/options` → `navigator.credentials.create()` → `POST /auth/passkeys/register/verify`; аналогично для входа с `navigator.credentials.get()`.
- Хранить `credential_id`, публичный ключ, `sign_count`, транспорт, имя устройства; проверять рост `sign_count` (защита от клона).
- Challenge одноразовый, живёт в Redis с TTL 5 минут; `rp_id` и `origin` строго из настроек окружения.
- Fallback для устройства без passkey: magic link на email (токен из T4.6).
- Страница «Способы входа»: список passkeys, переименовать, удалить; нельзя удалить последний способ входа.
- Discoverable credentials (вход без ввода email) — опционально.

## Критерии приёмки
- [ ] Вход по passkey с другого `origin` (например, `127.0.0.1` вместо `localhost`) отклоняется
- [ ] Повторное использование challenge → ошибка
- [ ] Тест с `sign_count`, не возросшим относительно сохранённого, → вход отклонён, событие в audit log (T5.7, если уже есть)

## Теория и ссылки

- Почему passkey устойчив к фишингу: привязка к origin, нет общего секрета на сервере
