# T2.1 Async SQLAlchemy + asyncpg

**Фаза:** P2 · **Слой:** backend, python · **Зависит от:** P0 · **Размер:** M

## Контекст
Эндпоинты объявлены как `async def`, но репозиторий работает через синхронную `Session` и psycopg:

```python
@router.get("")
async def get_notes(user: CurrentUserDep, repository: RepositoryDep):
    return [... for note in repository.get_notes(user.id)]  # sync-запрос к БД внутри async
```

Пока один запрос ждёт Postgres, **весь event loop стоит** — остальные запросы (даже `/health`) не обслуживаются. Под нагрузкой сервер ведёт себя как однопоточный.

## Цель
Весь доступ к БД асинхронный; один медленный запрос не блокирует остальные; пул соединений настроен осознанно.

## Что сделать

### 1. Эксперимент «до»
Добавь временный эндпоинт `GET /debug/slow`, который делает `SELECT pg_sleep(2)` через текущую sync-сессию. Запусти параллельно 5 запросов к нему и 1 к `/health` (`oha`, `hey` или скрипт на `httpx.AsyncClient` + `asyncio.gather`). Запиши время ответа `/health`.

### 2. Engine и сессия
- Драйвер: `postgresql+asyncpg://` (или `postgresql+psycopg://` в async-режиме — выбор в ADR, с учётом Supabase pooler из T1.2).
- `create_async_engine(url, pool_size=..., max_overflow=..., pool_pre_ping=True, pool_recycle=...)`.
- `async_sessionmaker(engine, expire_on_commit=False)`.
- Зависимость:

```python
async def get_session() -> AsyncIterator[AsyncSession]:
    async with session_factory() as session:
        yield session
```

- Транзакция — в service: `async with session.begin(): ...`.
- `statement_timeout` на уровне соединения (например 5 с) — зависший запрос не держит соединение вечно.

### 3. Репозитории
- Все методы `async`, `await session.execute(...)` / `await session.scalars(...)`.
- Никакого lazy loading: связи — через `selectinload` / `joinedload` явно, иначе `MissingGreenlet`.
- Базовый generic-репозиторий по желанию: `class Repository(Generic[ModelT])` с `get`, `add`, `delete`.

### 4. Alembic
`alembic/env.py` в async-режиме (`async_engine_from_config` + `connection.run_sync(do_run_migrations)`).

### 5. Тесты
- `pytest-asyncio` (`asyncio_mode = "auto"`), `httpx.AsyncClient` + `ASGITransport` вместо `TestClient`.
- Каждый тест в транзакции с откатом (или отдельная БД на сессию тестов) — тесты не видят данных друг друга.

### 6. Эксперимент «после»
Повтори замер из шага 1. `/health` должен отвечать мгновенно, пока идут медленные запросы. Удали `/debug/slow`.

## Python-фокус
- Что такое event loop и почему блокирующий вызов в `async def` хуже, чем `def` (FastAPI запускает `def`-эндпоинты в threadpool).
- `async with`, `AsyncIterator`, асинхронные генераторы как зависимости.
- Правило ruff `ASYNC` — какие вызовы он ловит.

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| `note.tags` после закрытия сессии | lazy load в async → `MissingGreenlet` |
| Одна `AsyncSession` на несколько корутин в `gather` | сессия не потокобезопасна и не для конкурентного использования |
| `pool_size=100` «на всякий случай» | Supabase режет соединения; пул × инстансы > лимита БД |
