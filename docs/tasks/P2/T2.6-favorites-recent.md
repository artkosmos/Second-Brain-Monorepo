# T2.6 Избранное и недавние

**Фаза:** P2 · **Слой:** backend, frontend · **Зависит от:** T2.2 · **Размер:** S

## Цель
В сайдбаре секции «Избранное» (ручной порядок) и «Недавние» (последние открытые), как в Notion.

## Модель данных
```
favorites    (user_id, page_id) PK, position text, created_at
page_visits  (user_id, page_id) PK, visited_at timestamptz
INDEX page_visits (user_id, visited_at DESC)
```

## API

| Метод | Путь | Что делает |
| ----- | ---- | ---------- |
| `PUT` | `/pages/{id}/favorite` | добавить (идемпотентно) |
| `DELETE` | `/pages/{id}/favorite` | убрать (идемпотентно) |
| `POST` | `/favorites/{page_id}/move` | `{after_id}` — порядок (fractional index из T2.3) |
| `GET` | `/favorites` | список |
| `POST` | `/pages/{id}/visit` | отметить посещение |
| `GET` | `/pages/recent?limit=10` | недавние |

## Бизнес-правила
1. Visit — upsert одной строкой:
   ```sql
   INSERT INTO page_visits (user_id, page_id, visited_at) VALUES (...)
   ON CONFLICT (user_id, page_id) DO UPDATE SET visited_at = excluded.visited_at;
   ```
   В SQLAlchemy — `postgresql.insert(...).on_conflict_do_update(...)`.
2. Удалённые страницы (T2.4) не показываются ни в избранном, ни в недавних.
3. Хранить в `page_visits` не больше N последних на пользователя — подрезка при вставке или периодически.
4. `PUT` / `DELETE` favorite идемпотентны: повтор не ошибка.

## Frontend
- Звёздочка в шапке страницы; optimistic toggle (`onMutate` → откат в `onError`).
- Секции в сайдбаре; drag-and-drop порядка избранного.
- Visit отправляется при открытии страницы, не чаще раза в минуту на страницу (троттлинг на клиенте).

## Критерии приёмки
- [ ] Многократный visit не создаёт новых строк (тест)
- [ ] Повторный `PUT` / `DELETE` favorite возвращают успех
- [ ] Удалённая страница исчезает из обеих секций
- [ ] Optimistic toggle откатывается при ошибке сервера
