# T2.4 Корзина: soft delete и restore

**Фаза:** P2 · **Слой:** backend, frontend · **Зависит от:** T2.2 · **Размер:** M

## Контекст
`DELETE` сейчас удаляет страницу с поддеревом безвозвратно. Случайный клик — потеря данных. В Notion удалённое уходит в корзину на 30 дней.

## Цель
Удаление обратимо: страница с поддеревом попадает в корзину, восстанавливается на место, через 30 дней удаляется навсегда.

## Модель данных
```
pages
  + deleted_at   timestamptz NULL
  + deleted_root uuid NULL    -- id страницы, которую удалили явно (для всего её поддерева)
INDEX ... WHERE deleted_at IS NULL   -- partial index под все обычные запросы
```

`deleted_root` нужен, чтобы отличать «удалил эту страницу» от «удалил родителя» и восстанавливать поддерево целиком.

## API

| Метод | Путь | Что делает |
| ----- | ---- | ---------- |
| `DELETE` | `/pages/{id}` | soft delete поддерева (одним `UPDATE` по CTE) |
| `GET` | `/trash` | только явно удалённые (`id = deleted_root`), с датой |
| `POST` | `/pages/{id}/restore` | восстановить поддерево |
| `DELETE` | `/trash/{id}` | удалить навсегда (hard delete поддерева) |

## Бизнес-правила
1. Все обычные запросы (дерево, страница, крошки, блоки, позже поиск) **по умолчанию** не видят удалённое. Реализация — в одном месте (базовый фильтр в репозитории или `with_loader_criteria`), а не `WHERE deleted_at IS NULL` в каждом методе вручную.
2. Прямой URL удалённой страницы → 404 (а в UI — экран «страница в корзине, восстановить?» по отдельному запросу).
3. Restore: если родитель тоже в корзине или удалён навсегда — восстановить в корень (и сообщить об этом в ответе).
4. Повторный restore / delete — идемпотентен (не 500).
5. Purge: страницы с `deleted_at < now() - 30 days` удаляются навсегда. Пока — CLI-команда `uv run python -m app.scripts.purge_trash` (в P5 станет cron-задачей в очереди). Удаление пачками (`LIMIT 1000` в цикле), чтобы не держать долгую блокировку.

## Frontend
- После удаления — toast «Страница удалена» с кнопкой «Отменить» (5 с) → restore.
- Раздел «Корзина» в сайдбаре: список, поиск по названию, «Восстановить», «Удалить навсегда» с подтверждением.
- Открытие удалённой страницы по ссылке — баннер с восстановлением.

## Критерии приёмки
- [ ] Удалённая страница и её поддерево не видны ни в одном обычном эндпоинте (тест на каждый)
- [ ] Restore возвращает поддерево на место; restore при удалённом родителе — в корень
- [ ] Purge удаляет только старше 30 дней, пачками; тест с «подкрученным» временем
- [ ] `EXPLAIN` запроса дерева использует partial index
- [ ] Undo-toast работает

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| Фильтр `deleted_at IS NULL` руками в каждом запросе | забудешь в одном — удалённое «воскреснет» в выдаче |
| Удаление в корзину только корня без поддерева | дети остаются видимыми как сироты |
| Purge одним `DELETE` на миллион строк | долгая транзакция, блокировки, раздувание WAL |
