# T2.C Challenge: способы хранения дерева

**Фаза:** P2 · **Слой:** challenge · **Зависит от:** T2.2 · **Размер:** M

## Цель
Понять на цифрах, когда adjacency list + recursive CTE достаточно, а когда нужен другой способ хранения дерева.

## Что сделать
1. Скрипт генерации: 10 000 страниц, глубина до 15, неравномерное ветвление (несколько «толстых» разделов).
2. Три варианта (можно в отдельной схеме БД):
   - adjacency list + recursive CTE (текущий);
   - `ltree` (расширение Postgres, путь вида `root.a.b`, GiST-индекс);
   - closure table (`ancestor, descendant, depth`).
3. Для каждого замерить `EXPLAIN (ANALYZE, BUFFERS)`:
   - получить всё поддерево раздела;
   - хлебные крошки страницы на глубине 15;
   - перенести раздел с 2000 потомков;
   - проверить, является ли A предком B.
4. Таблица результатов + вывод в ADR: что выбираем и при каком масштабе стоит пересмотреть.

## Критерии приёмки
- [ ] Скрипт генерации воспроизводим (фиксированный seed)
- [ ] Таблица замеров для всех трёх вариантов и четырёх операций
- [ ] ADR с решением
