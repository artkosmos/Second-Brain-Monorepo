# T3.C Challenge: lost update тремя способами

**Фаза:** P3 · **Слой:** challenge · **Зависит от:** T3.5 · **Размер:** S

## Цель
Руками почувствовать lost update и сравнить способы защиты под нагрузкой.

## Что сделать
1. Временная модель: счётчик просмотров страницы `view_count`.
2. Наивная реализация: прочитать `view_count`, прибавить 1 в Python, записать. 100 параллельных инкрементов (`asyncio.gather`, отдельные сессии) → итог заметно меньше 100. Тест должен стабильно это показывать.
3. Починить тремя способами и прогнать тот же тест:
   - атомарный `UPDATE ... SET view_count = view_count + 1`;
   - `SELECT ... FOR UPDATE` + запись;
   - optimistic `version` + ретраи.
4. Замерить время 1000 инкрементов для каждого способа, таблица в PR.
5. Вывод: когда какой способ уместен. Бонус: почему настоящий счётчик просмотров лучше считать вообще не так (Redis `INCR` + периодический сброс в БД — к этому вернёмся в P5).
