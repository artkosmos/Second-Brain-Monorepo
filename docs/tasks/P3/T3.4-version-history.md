# T3.4 История версий

**Фаза:** P3 · **Слой:** backend, frontend · **Зависит от:** T2.3 · **Размер:** L

## Контекст
Удалил абзац неделю назад — вернуть нельзя. В Notion есть «Page history»: список версий, просмотр, восстановление.

## Цель
У каждой страницы есть история снапшотов; любую версию можно посмотреть, сравнить с текущей и восстановить.

## Модель данных
```
page_versions
  id           uuid PK
  page_id      FK pages ON DELETE CASCADE
  version_no   int            -- 1, 2, 3 ... в пределах страницы
  title        text
  blocks       jsonb          -- снапшот: [{id, type, content, position}, ...]
  author_id    FK users
  reason       text           -- autosave | restore | manual
  created_at   timestamptz
UNIQUE (page_id, version_no)
```

## Бизнес-правила
1. **Когда делать снапшот.** Не на каждый batch (иначе тысячи версий в час), а по правилу: прошло ≥ N минут с последнего снапшота страницы **и** были изменения. Проверка — в service при обработке batch (в P5 можно вынести в фоновую задачу через outbox).
2. Снапшот и изменение, которое его спровоцировало, — в одной транзакции.
3. Restore = **новая** версия с содержимым старой (`reason = restore`), история не переписывается. Restore тоже требует `If-Match` (T3.1).
4. Restore блоков: удалить текущие блоки страницы и вставить из снапшота **с исходными id** (ссылки, комментарии позже будут ссылаться на id блока).
5. Retention: хранить все версии за 7 дней, дальше — одну в день, старше 90 дней — удалять. Политика — в ADR; очистка — команда (в P5 — cron).
6. Размер: снапшот целиком в JSONB — просто, но дорого для больших страниц. В ADR оценить и сравнить с хранением diff-ов (delta) — реализовать можно простой вариант.

## API

| Метод | Путь | Что делает |
| ----- | ---- | ---------- |
| `GET` | `/pages/{id}/versions` | список (keyset из T2.5): номер, автор, время, причина |
| `GET` | `/pages/{id}/versions/{no}` | содержимое версии |
| `GET` | `/pages/{id}/versions/{no}/diff?against=current` | изменения по блокам: added / removed / changed |
| `POST` | `/pages/{id}/versions/{no}/restore` | восстановить |

Diff по блокам считается на бэке по `id` блоков; для изменённого текста — `difflib` построчно / по словам.

## Frontend
- Панель «История» справа: список версий с относительным временем.
- Просмотр версии read-only с подсветкой: добавленные блоки — зелёным, удалённые — красным, изменённый текст — inline-diff.
- «Восстановить» с подтверждением; после — toast с «Отменить» (это просто restore предыдущей версии).

## Python-фокус
- `difflib.SequenceMatcher` / `ndiff` для текстового diff.
- `dataclass` / Pydantic для снапшота блока; сериализация в JSONB и обратно с валидацией (старые снапшоты должны читаться после изменения схемы блоков — подумай о версии формата снапшота).

## Критерии приёмки
- [ ] Снапшоты создаются по правилу частоты (тест с подкрученным временем)
- [ ] Restore создаёт новую версию, старые не меняются; восстановленные блоки имеют исходные id
- [ ] Diff корректен для добавления, удаления, перемещения и изменения блока
- [ ] Retention-очистка работает и покрыта тестом
- [ ] UI истории, просмотр, diff, восстановление с undo

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| Снапшот на каждое нажатие | таблица растёт в сотни раз быстрее страниц |
| Restore перезаписывает историю | нельзя отменить неудачное восстановление |
| Снапшот без версии формата | изменишь схему блоков — старые версии не прочитаются |
