# T3.1 Optimistic locking: ETag и If-Match

**Фаза:** P3 · **Слой:** backend, frontend, system-design · **Зависит от:** T2.3 · **Размер:** M

## Контекст
Страница открыта в двух вкладках. Вкладка A меняет заголовок, вкладка B (со старыми данными) — иконку через `PUT`. B молча затирает изменение A: это **lost update**.

## Цель
Сервер отклоняет запись, основанную на устаревшей версии; пользователь видит конфликт и сам решает, что сохранить.

## Модель данных
```
pages  + version integer NOT NULL DEFAULT 1
blocks + version integer NOT NULL DEFAULT 1
```

## Протокол
1. `GET /pages/{id}` возвращает заголовок `ETag: "page-<id>-v<version>"` (и `version` в теле).
2. `PATCH /pages/{id}` и `POST /pages/{id}/move` требуют `If-Match: "<etag>"`:
   - заголовка нет → `428 Precondition Required`;
   - версия не совпала → `412 Precondition Failed`, в теле Problem Details — текущая серверная версия страницы;
   - совпала → запись, `version + 1`, новый `ETag` в ответе.
3. Проверка и запись — **одним атомарным запросом**, а не «прочитал, сравнил, записал»:
   ```sql
   UPDATE pages SET title = :title, version = version + 1
   WHERE id = :id AND owner_id = :uid AND version = :expected
   RETURNING *;
   ```
   0 строк → отличить «нет такой страницы» (404) от «версия устарела» (412) вторым дешёвым запросом.
   Альтернатива — `version_id_col` в маппере SQLAlchemy (`StaleDataError`). Выбор — в PR.
4. Блоки в batch (T2.3): у операции `update` / `move` / `delete` — поле `expected_version`; конфликт одной операции → весь batch 409 с перечнем конфликтных блоков.
5. `GET` с `If-None-Match` совпавшим → `304 Not Modified` (бонус: экономия трафика).

## Frontend
- Сгенерированный клиент хранит `ETag` из ответа и отправляет `If-Match` автоматически (обёртка над мутациями).
- 412 → диалог: «Страница изменена в другом месте». Варианты: «Взять серверную версию», «Перезаписать моей» (повтор с новым ETag), для заголовка — показать обе версии рядом.
- Диалог доступен с клавиатуры, фокус в нём ловится (focus trap), Esc закрывает.

## Python-фокус
- Свой exception `StaleVersionError` в домене → обработчик в HTTP-слое превращает его в 412. Домен не знает про HTTP.
- Разбор заголовков: `Header()` в FastAPI, формат ETag (strong vs weak `W/`).

## Критерии приёмки
- [ ] Тест: два PATCH с одним `If-Match` параллельно (`asyncio.gather`) — один 200, второй 412
- [ ] PATCH без `If-Match` → 428
- [ ] 412 содержит актуальную версию; фронт показывает диалог и умеет разрешить конфликт обоими способами
- [ ] Batch блоков: конфликт одной операции откатывает весь batch
- [ ] `GET` с `If-None-Match` → 304

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| `SELECT` версии, сравнение в Python, затем `UPDATE` | между ними успеет записать другой запрос |
| ETag = хэш всего ответа на каждый GET | дорого и ломается при изменении формата ответа |
| Last-write-wins «и так сойдёт» | пользователь теряет правки и не узнаёт об этом |
