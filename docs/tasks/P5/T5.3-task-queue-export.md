# T5.3 Очередь задач, экспорт и импорт

**Фаза:** P5 · **Слой:** backend, frontend · **Зависит от:** T5.1 · **Размер:** L

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы.

## Backend
- ADR: `arq` vs `Taskiq` vs Celery.
- Отдельный процесс-воркер: свой сервис в compose и на PaaS.
- Задача «экспорт workspace в Markdown zip»; статус задачи (`queued / running / done / failed`, прогресс %).
- Обратная задача «импорт Markdown zip» (свой экспорт и экспорт Notion / Obsidian): парсинг в блоки из T2.3, восстановление дерева по папкам и внутренних ссылок, отчёт «что не распозналось». Импорт в отдельную ветку дерева, чтобы было легко откатить.
- Общий контракт долгих операций: `POST …` → `202 Accepted` + `job_id`, `GET /jobs/{id}` — статус. Этот же контракт потом используют AI-операции (P11).
- Перенести в очередь purge корзины (T2.4), очистку ключей идемпотентности (T3.2), retention версий (T3.4) и письма инвайтов (T4.4); cron-задачи.

## Frontend
- Кнопки «Экспорт» и «Импорт», прогресс (polling; в P7 — push), скачивание результата, отчёт импорта.

## Критерии приёмки
- [ ] Рестарт воркера посреди задачи → задача доезжает или корректно `failed`
- [ ] Задача идемпотентна: повторный запуск не ломает результат
- [ ] Graceful shutdown воркера: текущая задача дорабатывает
- [ ] Round-trip: экспорт → импорт в пустой workspace даёт то же дерево и те же блоки (тест)
- [ ] Zip-бомба и путь `../` в архиве отклоняются до распаковки
