# T5.4 Transactional outbox

**Фаза:** P5 · **Слой:** backend, system-design · **Зависит от:** T5.3 · **Размер:** L

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы.

## Backend
- Таблица `outbox` пишется в той же транзакции, что и изменение страницы.
- Relay читает `FOR UPDATE SKIP LOCKED` и публикует в очередь или Redis Streams.
- Потребители идемпотентны (таблица обработанных `event_id`).
- События `page.created / page.updated / page.deleted`.

## Критерии приёмки
- [ ] Упал брокер → события не теряются, доезжают после восстановления
- [ ] Дубль события не ломает потребителя
- [ ] Порядок событий в пределах одной страницы сохраняется

## Теория
- Dual-write problem, at-least-once delivery.
