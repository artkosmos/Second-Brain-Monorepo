# T11.1 Суммаризация со стримингом

**Фаза:** P11 · **Слой:** backend, frontend · **Зависит от:** T5.2, T5.5 · **Размер:** M

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы.
> **Рекомендуется брать сразу после P5**, не дожидаясь P11: зависимости готовы, а первая AI-фича рано показывает, где платформа течёт.

## Backend
- Абстракция `LLMProvider` (`Protocol`): `complete()`, `stream()`, `count_tokens()`; реализации — OpenAI, OpenAI-совместимый (любой gateway), `FakeProvider` для тестов с детерминированным выводом и задержками.
- `POST /pages/{id}/summarize` → SSE (`StreamingResponse` + async-генератор); события `delta`, `usage`, `done`, `error`; отмена генерации при разрыве соединения (`request.is_disconnected()`, отмена задачи провайдера).
- ADR `00NN-ai-stream-protocol.md`: свой формат SSE vs протокол Vercel AI SDK UI Message Stream vs AG-UI. Критерии: готовые React-хуки, поддержка tool calls и approvals (понадобятся в T11.5), простота тестирования.
- Structured output через Pydantic: вариант «краткое резюме + 3 ключевых тезиса» как схема, валидация и один повтор при невалидном JSON.
- Prompt caching провайдера: системный промпт и содержимое страницы — в кэшируемый префикс; в логах видно, сколько токенов пришло из кэша.
- Таймауты, retry, breaker из T5.5; при открытом breaker — понятная ошибка «AI временно недоступен», а не 500.
- Лимит токенов и затрат на пользователя и на workspace в день (Redis, T5.2); учёт стоимости по прайсу модели в `ai_usage (workspace_id, user_id, model, prompt_tokens, completion_tokens, cached_tokens, cost_usd, feature)`.
- Промпты — в коде как версионированные константы (`prompts/summarize_v1.py`), версия пишется в `ai_usage`; переключение версии — через feature flag (T9.5), когда он появится.

## Frontend
- Вывод по мере генерации, кнопка «Стоп», вставка результата блоком (batch из T2.3), индикатор «из кэша / стоимость».

## Python-фокус
- Async-генераторы, `aclose()` и `finally` при отмене; `asyncio.timeout`; `Protocol` с async-методами.

## Критерии приёмки
- [ ] Закрыл вкладку → запрос к провайдеру отменён (тест с `FakeProvider`, считающим, дошёл ли он до конца)
- [ ] Превышение лимита → 429 с понятным текстом и заголовком, когда можно снова
- [ ] Невалидный JSON от модели → один retry, затем 502 с Problem Details, пользователь видит объяснение
- [ ] `ai_usage` содержит стоимость каждого вызова; сумма за день совпадает с лимитом из Redis
- [ ] ADR по протоколу стриминга написан
