Проект сделан — теперь его нужно уметь объяснить за 10 минут и показать за 3. Это отдельная работа, и её обычно не делают.

## Что сделать
1. `docs/architecture.md`: C4-диаграммы уровня Context и Container (Mermaid), поток данных для трёх сценариев — «правка блока» (batch → outbox → индексация → WS), «RAG-ответ» (retrieval → rerank → LLM → цитаты), «вызов из MCP-клиента» (токен → scope → инструмент → audit). Ключевые инварианты (права фильтруются до поиска, write-действия модели только через approval, at-least-once в webhooks) — списком со ссылками на тесты.
2. Сводка ADR: таблица всех решений с датой, статусом и ссылкой; для 3–5 главных — «что бы решил иначе сегодня и почему».
3. Пост-мортем проекта: что заняло дольше всего, какие задачи оказались лишними, какие баги нашли hypothesis / chaos / DR-учения, что из роадмапа не сделано и осознанно.
4. README для портфолио: один абзац «что это», скриншоты или gif ключевых фич, стек, ссылка на staging с demo-аккаунтом, как поднять локально одной командой, ссылки на архитектуру и ADR.
5. Демо-видео 3–5 минут: регистрация → редактор → шаринг → поиск → AI-действие с approval → тот же workspace из Cursor через MCP.
6. Нагрузочный и eval-отчёты (T9.2, T11.4) — актуальные версии приложены к README.
7. Опционально: статья или доклад по одной теме, где решение было нетривиальным (fractional indexing, outbox + embeddings, SSRF-safe fetcher, approval в агентном цикле).
