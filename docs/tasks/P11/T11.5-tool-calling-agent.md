# T11.5 Tool calling и агентный цикл

**Фаза:** P11 · **Слой:** backend, frontend, python · **Зависит от:** T11.1, T9.5 · **Размер:** L

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы. Поглощает бывший T11.C «AI-действия над страницей».

## Контекст
Суммаризация и чат только читают. Следующий шаг — модель **делает**: «преврати заметку в план задач», «найди все страницы про X и собери сводку», «разложи эту страницу по структуре». Для этого модели дают инструменты, а приложение крутит цикл «вызов → инструмент → результат → вызов». Цикл пишется руками, чтобы понимать, что потом делает фреймворк.

## Backend: цикл руками
- Инструменты как Pydantic-модели аргументов + функция; реестр инструментов, JSON Schema для провайдера генерируется из моделей. Стартовый набор: `search_pages`, `read_page`, `propose_blocks` (возвращает batch-операции T2.3, **не применяет**), `create_page` (deferred, см. approval).
- Цикл `run_agent()` в `modules/ai/agent.py`: шаг = запрос к модели → либо текст, либо вызовы инструментов → выполнение → результаты обратно. Лимиты: **шагов** (например, 10), **времени** (`asyncio.timeout`), **стоимости** (сумма из `ai_usage`, T11.1); превышение — понятная остановка с частичным результатом.
- Валидация аргументов инструмента Pydantic'ом; невалидный вызов → ошибка возвращается модели как результат инструмента («repair»), один повтор; после — остановка.
- Ошибки инструмента, которые модель может исправить (страница не найдена), отличаются от тех, что не может (БД недоступна) — вторые прерывают цикл.
- **Human approval перед любым write-действием:** инструменты помечены `requires_approval`; цикл приостанавливается, состояние (`agent_runs`, `agent_steps`) сохраняется в БД, фронт показывает diff; после подтверждения цикл продолжается с того же шага. Применение — обычный batch из T2.3 с `If-Match` (T3.1), версией (T3.4) и undo.
- Состояние прогона в БД, а не в памяти: перезапуск процесса между шагами → прогон продолжается (минимальная «durable execution»).
- Стриминг шагов на фронт по протоколу из ADR T11.1 (события `tool_call`, `tool_result`, `approval_required`).
- Инструменты идемпотентны по `step_id`: повторная доставка не создаёт вторую страницу.

## Backend: то же на фреймворке
- Повторить один сценарий на [Pydantic AI](https://ai.pydantic.dev/) (deferred tools для approval, `UsageLimits`); ADR «свой цикл vs Pydantic AI»: что фреймворк даёт (типизация, ретраи, approvals, OTel), что скрывает, где остаёмся на своём.
- Выбор сценария / версии системного промпта агента — через вариант feature flag (T9.5).

## Frontend
- Панель «AI-действие»: ввод команды, лента шагов (какой инструмент, с чем, что вернул), карточка approval с diff блоков «было / станет», кнопки «Применить / Отклонить», «Отменить» (undo через версию).

## Python-фокус
- Генерация JSON Schema из Pydantic и обратная валидация; `TypedDict` vs `BaseModel` для аргументов; конечный автомат прогона; сохранение и восстановление состояния async-цикла.

## Критерии приёмки
- [ ] Тест на `FakeProvider`: модель «зациклилась» (каждый шаг — один и тот же вызов) → остановка по лимиту шагов, пользователь видит причину, стоимость не превышает лимит
- [ ] Тест: write-инструмент без approval невозможен ни при каком ответе модели (инвариант в коде, а не в промпте)
- [ ] Тест: процесс убит после шага 3 из 6 → после рестарта прогон продолжается с шага 4
- [ ] Тест: невалидные аргументы инструмента → модель получает ошибку и исправляет; после второй неудачи — остановка
- [ ] Применённое действие откатывается через историю версий
- [ ] 10 кейсов на выбор инструмента добавлены в eval (T11.4): правильный ли инструмент и аргументы
- [ ] ADR «свой цикл vs фреймворк»

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| «Не делай ничего без разрешения» в промпте вместо кода | injection снимает ограничение одной фразой |
| Состояние прогона в памяти процесса | деплой посреди прогона = потерянная работа и деньги |
| Инструмент возвращает всю страницу на 50k токенов | контекст и бюджет сгорают за один шаг; нужны лимиты и пагинация внутри инструментов |
