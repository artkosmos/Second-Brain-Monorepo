# T11.6 MCP-сервер Second Brain

**Фаза:** P11 · **Слой:** backend, python · **Зависит от:** T11.5, T8.4 · **Размер:** L

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы.

## Контекст
[Model Context Protocol](https://modelcontextprotocol.io/) — стандарт, по которому Cursor, Claude, ChatGPT и другие клиенты подключают внешние инструменты. MCP-сервер Second Brain делает базу знаний доступной любому AI-клиенту пользователя, без своего чата. Это одна из самых сильных портфолио-задач в области и прямое применение всего, что сделано раньше: API-токены, scope, права, rate limit, audit log.

## Backend
- Официальный [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk); транспорт **Streamable HTTP**, смонтирован в то же FastAPI-приложение (`/mcp`) или отдельным сервисом — ADR (масштабирование, изоляция сбоев, общий пул БД).
- Авторизация: Bearer API-токен из T8.4; scope токена ограничивает доступные инструменты (least privilege: токен `pages:read` не видит `append_blocks` в списке инструментов, а не получает 403 при вызове). OAuth-поток авторизации MCP (Authorization Server metadata, dynamic client registration) — опционально, как расширение.
- Инструменты (переиспользуют реестр из T11.5, не дублируют логику): `search_pages(query, limit)`, `read_page(page_id)` с пагинацией блоков, `list_recent_pages()`, `append_blocks(page_id, blocks)` и `create_page(parent_id, title)` — write-инструменты требуют scope `pages:write` и пишут в audit log (T5.7).
- Ресурсы: `secondbrain://pages/{id}` как MCP resource; промпты: `summarize_page`, `weekly_review` как MCP prompts.
- Описания инструментов — часть контракта с моделью: короткие, с примерами, с ограничениями («возвращает не больше 20 результатов»). Тест на выбор инструмента (T11.4) гоняется и через MCP.
- Rate limit на токен (T5.2), лимит размера ответа инструмента, таймауты; все вызовы — в трейсе (T11.7) с `tool_name`, `token_id`, `workspace_id`.
- Stateless по спецификации: никакого состояния сессии в памяти процесса — иначе второй инстанс за балансировщиком (T7.C) ломает клиента.

## Проверка
- [MCP Inspector](https://github.com/modelcontextprotocol/inspector) против локального сервера.
- Реальный клиент: Cursor или Claude Desktop с конфигом на staging-URL; сценарий «найди мои заметки про X и добавь итог в страницу Y» проходит с approval на стороне клиента.
- Контрактные тесты через клиент из SDK: список инструментов зависит от scope, вызовы валидируются.

## Python-фокус
- Декораторы SDK и генерация схем из type hints; `anyio` внутри SDK и совместимость с asyncio-приложением; структурированные ошибки инструментов.

## Критерии приёмки
- [ ] Токен `pages:read` видит только read-инструменты в `tools/list`; вызов write-инструмента таким токеном → ошибка авторизации, запись в лог
- [ ] Тест: `read_page` чужой страницы → «not found», содержимое не утекает
- [ ] Сервер работает за балансировщиком на двух инстансах (сценарий T7.C), клиент не замечает переключения
- [ ] Сценарий в Cursor / Claude Desktop записан как короткое демо (gif или видео) в `docs/`
- [ ] Отозванный токен → следующий вызов инструмента отклонён
- [ ] ADR «встроенный `/mcp` vs отдельный сервис»

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| Инструмент возвращает всё дерево workspace | контекст клиента переполняется; нужна пагинация и лимиты в самом инструменте |
| Описание инструмента «Does stuff with pages» | модель выбирает не тот инструмент; описание — это промпт |
| Сессия MCP в памяти процесса | не масштабируется, падает при деплое |
