# T6.5 Bookmark-блок и SSRF-безопасный link preview

**Фаза:** P6 · **Слой:** backend, frontend, system-design · **Зависит от:** T5.3 · **Размер:** M

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы.

## Контекст
Вставил ссылку — получил карточку с заголовком, описанием и картинкой. Для этого сервер ходит по URL, который прислал пользователь. Это классический вектор SSRF (OWASP API7): через такой fetcher достают метаданные облака (`169.254.169.254`), внутренний Redis или админку. Задача — сделать фичу и закрыть вектор.

## Backend
- Блок `bookmark` (discriminated union из T2.3): `url`, `title`, `description`, `image_url`, `site_name`, `status: pending | ready | failed`.
- Превью считается в очереди (T5.3), не в запросе; результат пушится клиенту (в P7 — через WS, до этого — polling).
- Fetcher `core/safe_http.py`:
  - только `http` / `https`, порт 80 / 443 (или явный allow-list);
  - DNS-резолв **до** запроса и проверка всех A / AAAA адресов: запрет loopback, link-local, private (RFC 1918), ULA, `0.0.0.0/8`, metadata-диапазонов; соединение — по уже проверенному IP (защита от DNS rebinding);
  - редиректы вручную, не более 3, каждый hop проходит те же проверки;
  - таймауты connect / read, лимит размера тела (например, 1 МБ), лимит на `Content-Type` (`text/html` для страницы, `image/*` для картинки);
  - картинка превью не хотлинкуется — скачивается тем же fetcher'ом и кладётся в S3 (T5.6), чтобы браузер пользователя не ходил на чужой хост.
- Парсинг Open Graph / `<title>` / `<meta name="description">` через `selectolax` или `beautifulsoup4`; HTML не исполняется.
- Кэш результата по URL (Redis, TTL сутки); rate limit на число превью в минуту на пользователя.

## Frontend
- Вставка URL в пустой блок → предложение «сделать закладку»; карточка с состояниями pending / ready / failed и кнопкой «повторить».

## Python-фокус
- `httpx` с кастомным транспортом / `AsyncHTTPTransport` и явным резолвом через `anyio.getaddrinfo`; `ipaddress` для классификации адресов.

## Критерии приёмки
- [ ] Тесты: `http://127.0.0.1`, `http://169.254.169.254/latest/meta-data`, `http://[::1]`, домен, резолвящийся в `10.0.0.1`, редирект с публичного URL на приватный — все отклонены с понятной ошибкой, в лог попадает причина
- [ ] Тест: ответ 50 МБ обрывается на лимите, задача завершается `failed`, воркер не падает по памяти
- [ ] Тест: `file:///etc/passwd`, `gopher://`, `ftp://` отклоняются до сетевого вызова
- [ ] Превью не блокирует сохранение блока: страница сохраняется сразу, карточка дорисовывается позже

## Частые ошибки
| Антипаттерн | Почему плохо |
| ----------- | ------------ |
| Проверка hostname регуляркой, а не IP после резолва | `localtest.me`, DNS rebinding, десятичная запись IP обходят проверку |
| `follow_redirects=True` в клиенте | первый URL публичный, второй — `http://10.0.0.5/admin` |
| Хотлинк `image_url` в карточке | браузер каждого читателя стучится на чужой сервер; IP-утечка читателей |
