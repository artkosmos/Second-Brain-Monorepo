# T10.1 VPS как код и prod-compose

**Фаза:** P10 · **Слой:** infra · **Зависит от:** P1 · **Размер:** L

> Короткая карточка. Подробное ТЗ пишется перед стартом фазы.

## Infra
- VPS (Hetzner или любой), SSH только по ключу, firewall (открыты только 22 / 80 / 443), отдельный пользователь для деплоя, автообновления безопасности.
- **Сервер настраивается кодом, не руками.** ADR: Ansible (плейбук в `infra/ansible/`) vs cloud-init (`user-data` при создании VPS) vs оба (cloud-init — минимум для первого SSH, Ansible — всё остальное). Повторный запуск идемпотентен: ничего не меняет на уже настроенном сервере.
- Опционально: создание самого VPS через Terraform / OpenTofu (провайдер Hetzner) — тогда «сервер с нуля» = `tofu apply && ansible-playbook`.
- `infra/compose.prod.yaml`: Caddy (автоматический TLS), api × 2, worker, Postgres (или остаётся Supabase — ADR), Redis, MinIO.
- Секреты: [sops](https://github.com/getsops/sops) + [age](https://github.com/FiloSottile/age); зашифрованный `infra/secrets/prod.enc.env` лежит в git, ключ age — только у деплоящего и в GitHub Secrets для CD. На сервере — расшифрованный файл с правами 600, лимиты ресурсов контейнеров.
- Runbook `docs/runbooks/new-server.md`: как поднять сервер с нуля, как ротировать ключ age.

## Критерии приёмки
- [ ] Новый чистый VPS поднимается до «staging отвечает по HTTPS» одной командой (или одним скриптом) без ручных шагов, кроме указания IP и ключа
- [ ] Повторный прогон плейбука на настроенном сервере — `changed=0`
- [ ] `git log` не содержит секретов в открытом виде; `sops -d` с ключом разворачивает `.env`
- [ ] Staging работает на VPS по HTTPS
- [ ] `docker compose ps` — все сервисы healthy
- [ ] Пройден базовый чеклист харденинга сервера (sshd config, fail2ban или аналог, unattended-upgrades)
